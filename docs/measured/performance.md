## How to read this

1. **The primary memory metric is VmHWM, not the paper's VmPeak**: ASan's shadow
   memory is a `MAP_NORESERVE` virtual reservation, so VmPeak is inflated to about
   20 TB and no ratio can be derived from it. The 3.37x of the 2012 paper reflects a
   real growth in resident memory.
2. **The gap between the two ASan columns comes mainly from the quarantine**:
   `quarantine=0` returns freed memory at once, while the default 256MB inflates the
   ratio of `malloc_heavy` substantially. The paper switched the quarantine off when
   measuring performance, so **the asan_paper column is the one comparable with the
   paper**.
3. The workloads are hand-written microbenchmarks, not SPEC CPU2006, so absolute
   values cannot be compared with 73% / 3.37x directly; what is comparable is the
   order of magnitude and the trend.

## How to reproduce

```
bash bench/run_bench.sh
single run: ASAN_OPTIONS=quarantine_size_mb=0:redzone=32:malloc_context_size=0 ./build/bench_asan malloc_heavy
```
